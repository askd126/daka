# Agent Note: 密码重登建立考勤团队会话并验证实际接口

Status: implemented

## Problem

2026-10-16 上班任务中，账号详情成功，但考勤规则和今日状态返回 code 999999、您的登录状态已失效。此前自动登录只验证密码接口与账号详情，未建立团队会话，误把无法考勤的 Cookie 视为有效。凌晨青龙从 Gitee 的旧提交重新同步，还覆盖了运行目录新版核心。

## Decision

密码登录后读取可用团队，选择明确配置的 teamNo，并按官方门户调用 api-link-saas/v3/team/change（terminal 2）。只有一个团队时允许自动选择，多团队必须指定，重新保存配置留空沿用原团队。随后验证考勤规则和今日状态，全部成功才返回可保存 Token。团队编号和凭据一同持久化，定期更新与单次过期恢复共用该完整流程。

认证错误识别补充登录状态已失效消息；不把所有 code 999999 归为过期，避免误判其他业务故障。恢复请求超时覆盖完整登录、选团队及写回操作。通知和打卡策略保持不变，诊断不提交打卡。

## Alternatives considered

切换密码响应 otherToken 无法修复：实际两个 Token 都能查账号但都无法读取考勤。靠账号详情成功判定登录有效验证成本低，却覆盖不了考勤会话，故要求实际考勤只读接口通过。自动选择首个团队无需额外设置，却可能打错团队，因此多团队必须明确选择。

## Consequences

登录多了团队选择和只读验证请求；多团队账号必须填写团队编号。账号详情成功不能再被称为考勤登录成功。仅更新运行目录仍可能被旧订阅覆盖，订阅源调整需要用户确认，不擅自向 Gitee 推送。历史失败不能通过修复登录自动补报打卡成功。

## Testing

真实接口验证：密码登录 Token 与 otherToken 均返回考勤失效；切换经核对的目标团队后，规则与今日状态均成功，今日状态姓名与用户目标相符。单元测试覆盖单团队自动选择、多团队需指定、团队不匹配、账号详情成功而考勤失败，以及 code 999999 的消息分类。后续实际验证使用已保存 Token 读取规则和今日状态，不提交打卡。
