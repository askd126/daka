# Agent Note: 青龙打卡的日期、缓存与失败复核

Status: implemented

## Problem

青龙容器的本地时区可能不是北京时间；节假日数据源网络波动会直接中断打卡。今日状态的其他日期记录可能导致请假误判，而打卡请求已被服务端受理但响应丢失时可能重复提交。

## Decision

任务按北京时间生成日期和默认班次，节假日查询成功后写入按年份保存的本地缓存；在线源全部失败时读取缓存，缓存也不可用才安全失败。请假判断只使用能确认属于今天的记录。提交重试耗尽后重新查询对应班次，若服务端已记录打卡则按成功处理。HTTP 错误保留短响应片段，便于排查业务错误。

缓存也用于[周末与节假日相连的规则](../feature/2026-09-28-weekend-attendance-rule.md)。

## Alternatives considered

仅依赖在线节假日数据实现最简单，但短时网络故障会漏打卡；完全忽略查询失败则可能在节假日误打卡。缓存已确认的年度数据保留了安全失败边界。

## Consequences

脚本目录需要可写才能持久化缓存；写入失败不会中断当次任务。缓存数据可能在官方安排修订后过时，因此每次任务仍先尝试在线查询。失败后的状态复核增加一次读取请求，但减少重复打卡与误报失败。

## Verification

`node --test qinglong/*.test.cjs` 覆盖节假日离线回退、无缓存安全失败、周末规则和请假识别；`node --check qinglong/hik_daka.js` 验证脚本语法。
