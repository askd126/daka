# Agent Note: Token 前端兼容青龙订阅脚本目录

Status: implemented

## Problem

前端启动、容器 helper、Linux 安装预检和开机等待都假定核心脚本位于 `/ql/data/scripts/hik_daka.js`。青龙公开仓库订阅可保留仓库及 qinglong 子目录；订阅成功仍会被误报为核心脚本缺失。Docker 未运行等错误也被原来的 test -f 检查混同为文件缺失。

## Decision

四个入口共用 `ql_token_admin.cjs` 的路径解析器。在容器内扫描 `/ql/data/scripts` 与旧版 `/ql/scripts` 及其订阅子目录，跳过依赖目录，按真实路径去重。唯一匹配自动使用，多份时列出路径并要求 `QL_HIK_DAKA_PATH` 或 `--core-path` 明确选择。自动扫描深度最多八级，不递归目录符号链接；指定绝对路径可覆盖扫描范围。

宿主机通过 docker exec 执行同一解析函数，将解析结果作为 helper 的容器环境变量。helper 延迟加载青龙客户端和核心脚本，使宿主机也能安全导入解析器。解析器和业务 helper 保持在旧安装脚本已复制的同一个文件，避免新增运行时文件导致旧版本按固定清单升级时缺文件。helper 的 `--resolve-container` 模式供安装和启动脚本调用；JSON stdin 操作契约保持不变。

Docker 错误保留原始原因。安装器持久化显式核心路径，支持 `--core-path auto` 清除选择。旧安装器自身仍带旧预检，因此首次升级本修复应运行最新仓库中的安装脚本。无需复制或修改用户的青龙核心脚本。

## Related decisions

[Linux 安装管理](../feature/2026-10-11-linux-token-admin-installer.md) 部分重叠并互链，本记录补齐其路径假设；[账号检测](../feature/2026-10-11-token-account-detection.md) 保持账号写入契约不变。已有通知路径修复属于核心模块加载通知程序的独立问题，不能替代前端定位核心脚本。检索未发现可完全吸收的路径解析记录。

## Alternatives considered

- 复制核心脚本到容器根目录能立即满足旧路径，但副本会脱离订阅更新，可能加载旧考勤规则；选择定位订阅原文件。
- 找到第一份即启动能减少用户选择，但 GitHub/Gitee 并行订阅或旧副本会让加载版本取决于遍历顺序；多份时要求显式选择。
- 单独新增运行时解析模块结构更独立，但旧安装器只复制固定文件清单，升级后会缺少新模块；解析函数复用现有 helper 文件。

## Consequences

订阅子目录可直接使用，手动、Windows、Linux 前端均获得相同路径兼容。多份脚本需要一次选择；运行环境必须允许读取脚本目录并在容器中执行 Node。解析函数仅依赖 Node 内置 fs/path，宿主机把函数源码传给容器执行；后续增加闭包依赖时必须同步容器执行上下文。此修复不改变账号、通知 Key 或考勤规则。

## Verification

Node 测试覆盖根目录、订阅子目录、重复根目录去重、多个核心文件、显式覆盖、缺失路径、依赖目录排除及 Docker 错误保留。隔离 Linux 安装测试只提供嵌套核心文件，真实运行解析器、服务及容器 helper（青龙客户端为只读测试替身），覆盖多份拒绝、显式选择和恢复自动定位。既有账号/UI 测试继续通过。真实本地青龙只读路径探测通过；用户 Ubuntu 的具体路径仍待现场输出确认。
