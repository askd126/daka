# Agent Note: 周末与节假日相连时的打卡规则

Status: implemented

## Problem

原脚本在周末直接绕过官方节假日查询，无法识别与节假日相连的周末，也没有独立周末的 80% 打卡规则。上、下班任务分开运行，若各自随机决定，可能同一天只打其中一次。

## Decision

青龙脚本按北京时间判断日期。周六、周日作为同一组，检查紧邻的周五、该周六、周日和周一；其中任一天在官方数据中标记为放假，就跳过整个周末。普通工作日只检查当天。

独立周末使用日期的 SHA-256 散列映射到 0 到 1 的区间，小于 0.8 时进入原有账号检查流程。这样长期约 80% 的独立周末会尝试打卡，同一天两个班次及所有账号的决定一致。请假、已打卡及“休息”考勤规则依旧在账号流程中跳过。节假日数据查询失败时，任务继续安全失败。

## Alternatives considered

每次任务调用 `Math.random()` 更直接，但同一天上、下班会独立抽签，重跑任务也可能改变结果，因此不用。

## Consequences

周末也需要读取节假日数据；跨年周末可能需要同时读取两个年份的数据。固定日期散列给出接近 80% 的长期比例，不保证每一个月或每一年恰好 80%。

## Testing

`node --test qinglong/hik_daka.test.cjs` 覆盖周五、周六和周一放假所连接的整个周末、跨年周末、同日两个班次的一致性、长期约 80% 的比例及请假识别。
