# Agent Note: Cookie 失效单次恢复与单次通知

Status: implemented

## Problem

十天定期更新无法覆盖提前失效的登录。任务直接报错会中断考勤，反复重跑也会重复提醒。

## Decision

青龙在 AUTH_EXPIRED 时调用宿主 Token 管理服务的专用恢复接口，凭容器内 600 权限桥接配置的独立随机密钥认证。密码留在宿主加密存储，接口只返回更新后的 Token 和通知标记。宿主服务沿用单队列串行处理，更新前重新读取青龙当前值；若其他任务已经更新，直接复用新值。

每个账号按失效 Token 的 SHA256 持久化事件，在登录前先占用事件。同一事件只尝试一次登录，重启仍去重。失败暂停该账号定期尝试，用户重新保存配置后恢复。无凭据账号只提醒一次。成功后任务仅重跑一次账号处理，仍失败时不递归恢复。检查模式不登录、不更新、不推送。

过期恢复结果使用个人通知一次；没有个人 Key 时进入系统汇总一次。有个人 Key 的恢复事件从汇总明细中排除，重复事件两边均静默。过期事件的个人通知不做发送重试，避免超时造成重复送达；其他日常账号推送沿用原策略。桥接不可用时容器持久化离线提醒摘要，避免重复提醒。

## Alternatives considered

在青龙保存账号密码能减少网络桥接，但复制敏感凭据并形成两份状态，故保持宿主统一存储。仅用进程内变量容易在任务重跑或服务重启后再次登录，故持久化事件摘要。专发一条登录结果再走个人与汇总会多次提醒，故复用现有结果通知并排除重复明细。

## Consequences

保证的是每次失效事件最多一次自动登录和通知发送尝试，网络或进程中断时不能保证通知必达。事件先落盘可防重复，但进程在登录前崩溃时需要人工重新保存配置。HTTP 桥接只在 Docker 宿主内部网络使用，密钥须保密，宿主监听地址需允许容器网关访问。10 天周期保持，失败事件暂停自动重试。订阅源仓库需同步，防止后续订阅覆盖。

## Testing

测试覆盖恢复成功、失败、无凭据、重启去重、普通错误不恢复、检查模式无副作用、新 Token 再失败不循环，以及汇总排除重复事件。


## Deployment verification

2026-10-15 已部署至 192.168.1.125，保留旧 release、原核心脚本及加密状态备份。服务器模拟 AUTH_EXPIRED 后通过真实桥接接口登录一次，更新原 Token 并仅作账号读取校验，未提交打卡。复用原 SendKey 发出一条明确标注模拟测试的通知，发送接口确认成功，无发送重试。账号数保持 2，其他账号及通知变量不变。相同事件重放返回 notify=false；服务重启后重放仍去重，lastSuccess 不变，证明没有额外登录。桥接配置权限为 600。单元测试 23 项及 Linux 安装器回归通过。

密码重登须建立团队会话并通过考勤接口验证，见 [考勤团队登录修复](../bug-fix/2026-10-16-login-attendance-team-context.md)。
